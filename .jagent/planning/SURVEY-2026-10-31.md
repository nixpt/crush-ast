## Method

- Every ticket parsed (table `| **Status** |` row or `**Status**:` line). Evidence base: `gh pr list --state all`
  (276 PRs: 245 merged, 25 closed, 6 open at start), `git log origin/main` (1,113 commits), and the code.
- Audit set: every status that is not Backlog/Done/Superseded, every `Done (PR pending/open/this PR)`, and the line-form
  tickets. Plus every Backlog ticket with a PR whose branch or title carries its ID, and every Backlog/In Progress
  ticket containing a Resolution/closure section.
- Decision rule: a ticket's own PR merged, claiming to implement it, with no "not in this PR / follow-up / half / core of"
  carve-out → **Done**. A carve-out, or unticked criteria the PR or ticket says remain → **In Progress**. No PR, no commit,
  and the code shows the gap → **Backlog**.
- Done tickets (134 before the survey): instead of a 20-ticket sample, all of them were checked for at least one merged PR
  or main commit citing the ID. Two had none by ID. Both check out: CRUSH-120 → merge `4858bd6` contains `ef3992c`;
  CRUSH-9 → `87ac57c`. This is an *existence* check, not a re-verification of each ticket's criteria.

## Judgment calls

1. **CRUSH-31/33/34 not renumbered.** Each is *one ticket in two files*, not two tickets sharing a number. The older
   file says "Superseded s412: canonical file is `CRUSH-3x-…`", and the newer, canonical file carries the work. Dozens
   of code comments (`crush-vm`, `crush-aot`, `crush-lang-sdk`, `crush-index`) and immutable commit subjects ("CRUSH-33
   Commit 2") mean the canonical file. Renumbering it, as "older keeps the ID" would require, would point all of them at
   a stub. The brief's own rule (newer gets a fresh ID) was deliberately not applied here. Options for a human: leave
   as is (PR #291 already grandfathers duplicates through an allowlist), or move the three superseded wrappers into
   `archive/`.
2. **"In Progress" for partly landed work.** The template has only Backlog / In Progress / Done. Tickets with merged
   slices and open criteria, but no open PR, are `In Progress — <what landed>; <what is open>` rather than Backlog.
   Dormant ones (CRUSH-34/36/37, last touched 2026-07/08) were left as In Progress. Resetting them to Backlog is a
   human call.
3. **Terminal states kept**: `Declined`, `Closed`, `Deferred` (6 tickets) are captain/owner decisions with no template
   equivalent, so they were left. `Superseded` (19) is the most common existing spelling beyond the template.
4. **`Captured` → `Backlog (captured idea)`** (CRUSH-21/22/23). No implementation evidence. Commits that say "CRUSH-21"
   were mislabelled CRUSH-71 work (`ecf51c1`).
5. **CRUSH-261 → Done** following sibling CRUSH-262's precedent (`Done (harness + baseline)`). Its second checkbox
   ("re-run after each of 257–260") is recurring.
6. **CRUSH-104, 161 → Done** with their foreman/captain publish checkboxes left unticked. The PRs merged; the
   irreversible publish steps were not re-verified.
7. **CRUSH-xps-10/11/12 → In Progress, not Done.** Their tickets (and BACKLOG-INDEX) say merging PR #213 "does not
   complete their review-exit matrices", and those criteria are still unticked.
8. **CRUSH-zorro-9/10/22/23/38/4 → Done.** Their wave PRs (#197, #198, #199, #209) implemented them without touching
   the ticket files. #199's follow-up notes are out of scope for these tickets.
9. **Index tables with no Status column** (BACKLOG-INDEX JS/TS spike and COSM, ROADMAP M5) got a one-line "status from
   the ticket files" summary instead of a new column.
10. **Generator scripts**: none for the tracked indexes. `jagent-ticket render` produces only the untracked
    `TASKS.md`; it was run as a parse check (187 done / 224 open lines) and not committed.
11. **`docs/planning` vs `.jagent/planning`**: `.jagent/planning` is canonical (its README; RULES apply to "anyone touching
    `.jagent/planning/`'s backlog"; ticket Status is the source of truth since `70a34d7`).
    `docs/planning/MIGRATION-INVENTORY.md` is CRUSH-150's research deliverable (cited by CRUSH-151–155), not a duplicate
    board, so it was left. `docs/tasks/*.md` are June 2026 pre-ticket task docs (one still says `Status: OPEN` for the
    JS frontend that now exists); they got a "historical, see the board" banner with content untouched.
