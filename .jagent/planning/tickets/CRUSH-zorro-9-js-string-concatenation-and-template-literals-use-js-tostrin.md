## Problem

`console.log('x' + 1.5 * 4)` prints `x6.0`; node prints `x6`. A `+` with a string operand (and probably template-literal interpolation of non-`/` floats) uses crush's float text, not JS ToString. #189 fixed only `console.log` arguments and `/`.

## Success criteria

- [ ] `'x' + 6.0`, `6.0 + 'x'`, `` `${1.5*4}` ``, `'a' + 1e21`, `'a' + 0.1*3` and `'a' + -0` match node.
- [ ] Number + number is unchanged (still numeric addition).
- [ ] Template literals use the **cooked** string, not the raw one: today `` `a\nb` `` prints a literal backslash-n (`q.raw` at lower_swc.rs ~1180/1191). Tagged templates keep `raw` for the tag's `.raw`.

## Technical approach

- When either operand of JS `+` may be a string, lower it to a JS-semantics add (e.g. a `js.add` capability: if either side is a string, ToString both with `conv.text(_, "js")`, else numeric add). Template literal parts go through `conv.text(_, "js")`.
- Mirror the new capability in both VMs and the AOT runtimes, as #189 did for `js.div`.

## Files to modify

- `crates/crush-lang-js/src/lower_swc.rs`
- `crates/crush-vm/src/{arithmetic,num_text,scheduler,portable_vm}.rs`
- `crates/crush-aot/src/{codegen,codegen_c}.rs`

## Non-goals

- Object-to-primitive conversion (`'' + {}`): loud for now.

## Dispatch

**The bar (from the spike, `.jagent/planning/research/2026-10-15-JS-TS-parity-spike.md`):** the crush VM prints byte-for-byte what `node` prints; the AOT Rust/C backends are exact **or fail at compile time**; nothing is ever silently wrong. Every case you fix lands as a corpus program under the harness (CRUSH-zorro-4) with a `.out` generated by real `node`.

- Work in a worktree under `crush-ast/.jagent/worktrees/<you>` (a sibling of the `buckets` symlink; deeper paths break the build).
- Reference implementation: `node` on PATH (v26; TypeScript runs with built-in type stripping). Never hand-write a `.out`.
- `crates/crush-lang-js/src/lower_swc.rs` is shared by most tickets. Until CRUSH-zorro-11 lands, keep edits local to the area you own and merge `origin/main` often; after it lands, add entries to the builtin/method table instead of new match arms.
- Gates before the PR: `cargo test -p crush-lang-js -p crush-lang-sdk -p crush-aot`, the walker set, and clippy. A new loud error must say what isn't supported, never "load from uninitialised slot".
