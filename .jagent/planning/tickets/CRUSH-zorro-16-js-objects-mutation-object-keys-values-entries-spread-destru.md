## Problem

Baseline: object literal plus `o.n += 1` plus `Object.keys` ("uninitialised slot"); `for-in` ("unknown capability: join" on the follow-up); spread `[...a]`/`{...o}` ("expected numeric, got null"); destructuring ("destructuring declarations are not supported yet").

## Success criteria

- [ ] Match node: property read/write/compound-assign, computed keys `o[k]`, `in`, `delete`, shorthand properties, `Object.keys`/`values`/`entries`/`assign`, array and object spread, array and object destructuring (declarations, nested, defaults, rest, and in function parameters), `for-in` over own keys in insertion order (after #188).
- [ ] Key order follows JS rules, including integer-like keys first and ascending, or that case is documented loud.
- [ ] Fixes what is silently wrong today (until then, CRUSH-zorro-23 makes these loud):
  - `for (k in arr)` yields elements, not index strings;
  - object spread `{...o}` is dropped;
  - every computed key `{[k]: v}` becomes the key `"[]"`;
  - setter bodies are dropped, and a getter isn't invoked on read;
  - `.length` on a variable holding `{length: 3}` lowers to `len`.

## Technical approach

- Split into sub-PRs if large: properties/Object.* → spread → destructuring.

## Dispatch

**The bar (from the spike, `.jagent/planning/research/2026-10-15-JS-TS-parity-spike.md`):** the crush VM prints byte-for-byte what `node` prints; the AOT Rust/C backends are exact **or fail at compile time**; nothing is ever silently wrong. Every case you fix lands as a corpus program under the harness (CRUSH-zorro-4) with a `.out` generated by real `node`.

- Work in a worktree under `crush-ast/.jagent/worktrees/<you>` (a sibling of the `buckets` symlink; deeper paths break the build).
- Reference implementation: `node` on PATH (v26; TypeScript runs with built-in type stripping). Never hand-write a `.out`.
- `crates/crush-lang-js/src/lower_swc.rs` is shared by most tickets. Until CRUSH-zorro-11 lands, keep edits local to the area you own and merge `origin/main` often; after it lands, add entries to the builtin/method table instead of new match arms.
- Gates before the PR: `cargo test -p crush-lang-js -p crush-lang-sdk -p crush-aot`, the walker set, and clippy. A new loud error must say what isn't supported, never "load from uninitialised slot".
