## Problem

There is a 14-program `node_corpus/` checked on the VM only. Nothing measures JS parity by feature area, nothing runs the JS corpus on the AOT backends, and TypeScript has no corpus at all. The spike's baseline (54 probes: 15 match, 33 loud, 6 silently wrong) lives only in a throwaway probe.

## Success criteria

- [ ] `crates/crush-lang-js/tests/node_corpus/` grows to cover every feature area of the spike's baseline table, one program per area (file prefix = area, e.g. `ops_typeof.js`), with `.out` produced by `node`.
- [ ] A corpus program that crush can't run yet is listed in a per-area **known-loud allow-list** that asserts it still fails *loudly*. If an entry starts matching, the test fails and asks for it to be removed (same pattern as `LOUD_ON_C` in `crates/crush-aot/tests/python_parity.rs`).
- [ ] Any program whose crush output differs from node **without an error** fails the test outright, labelled `SILENTLY WRONG`. That class is never allow-listed.
- [ ] `crates/crush-aot/tests/js_parity.rs`: the same corpus on AOT Rust and AOT C, exact-or-loud, mirroring `python_parity.rs`.
- [ ] TS twin: `tests/ts_corpus/*.ts`, the JS programs with type annotations added, run through the `ts` dialect and compared against `node <file>.ts` (type stripping).
- [ ] A freshness test re-runs `node` and fails if a `.out` is stale (skipped when node is absent).
- [ ] Seed the corpus from the spike's 54 baseline probes so the allow-list starts as the measured baseline.

## Technical approach

- Reuse `run_crush` / `crush_output_matches_node` from `node_corpus_test.rs`; add the allow-list and the silent-wrong classifier.
- Copy `python_parity.rs` for the AOT half.
- Keep each program small and single-purpose: the allow-list is the progress meter other tickets tick off.
