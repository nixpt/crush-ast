## Problem

Baseline, loud: `Math.floor`/`ceil`/`round`/`max`/`abs`/`sqrt`/`PI` ("unknown capability: math.floor"); `parseInt`/`parseFloat`/`Number`/`String`/`toString(16)`/`toFixed` ("unknown capability: parseInt"); `JSON.stringify`/`JSON.parse` ("unknown capability: json_stringify"); `new Map`/`new Set` ("unknown capability: new Map").

## Success criteria

- [ ] Match node: `Math.*` (floor, ceil, round with JS half-up, trunc, sign, abs, min/max varargs, pow, sqrt, cbrt, hypot, log/log2/log10/exp, sin/cos/tan/atan2, PI/E, `random` loud or seeded), `parseInt` (radix, partial strings), `parseFloat`, `Number()`, `String()`, `Number.isInteger`/`isFinite`/`isNaN`, `(n).toString(radix)`, `toFixed`, `JSON.stringify` (key order, spacing argument) and `JSON.parse` (reusing stdlib `json.*`), and `Map`/`Set` (`new`, `get`/`set`/`has`/`delete`/`size`, iteration order, `[...m]`).
- [ ] Fixes the `Math.trunc` "uninitialised slot" message noted in #189.

## Technical approach

- Registry rows mapping to stdlib `math.*`/`json.*`/`conv.*`; Map/Set may need a value representation decision (an ordered map with typed keys); note it in the PR.

## Files to modify

- registry
- stdlib
- AOT runtimes

## Non-goals

- `Date`, `RegExp`, `Intl`.

## Dispatch

**The bar (from the spike, `.jagent/planning/research/2026-10-15-JS-TS-parity-spike.md`):** the crush VM prints byte-for-byte what `node` prints; the AOT Rust/C backends are exact **or fail at compile time**; nothing is ever silently wrong. Every case you fix lands as a corpus program under the harness (CRUSH-zorro-4) with a `.out` generated by real `node`.

**Parser decision (owner, 2026-10-15): option B.** JS gets one frontend in crush-ast, a new `boa_parser` 0.22 lowering with a scope/semantic pass (**CRUSH-250**, widened; it absorbs bozo's BOZO-M7-1 design). swc stays only to strip TypeScript types (CRUSH-zorro-8). `lower_swc.rs` is frozen for `.js` apart from making silent constructs loud (CRUSH-zorro-23).

**Split of work:** the builtins semantics are **runtime-library** capabilities in crush-vm (`js.*`, mirrored in AOT). That's the shared JS runtime bozo's BOZO-M7-2 planned, now in crush-ast, and it can be built and unit-tested before CRUSH-250. Wiring them into the lowering uses CRUSH-250's builtin/method table. Read 'registry (after CRUSH-zorro-11)' above as 'CRUSH-250's table'.

- Work in a worktree under `crush-ast/.jagent/worktrees/<you>` (a sibling of the `buckets` symlink; deeper paths break the build).
- Reference implementation: `node` on PATH (v26; TypeScript runs with built-in type stripping). Never hand-write a `.out`.
- `crates/crush-lang-js/src/lower_swc.rs` is shared by most tickets. Until CRUSH-zorro-11 lands, keep edits local to the area you own and merge `origin/main` often; after it lands, add entries to the builtin/method table instead of new match arms.
- Gates before the PR: `cargo test -p crush-lang-js -p crush-lang-sdk -p crush-aot`, the walker set, and clippy. A new loud error must say what isn't supported, never "load from uninitialised slot".
