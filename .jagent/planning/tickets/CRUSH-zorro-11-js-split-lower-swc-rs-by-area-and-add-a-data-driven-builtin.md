## Problem

**Superseded 2026-10-15 by the parser decision (option B).** `.js` moves to a new `boa_parser` 0.22 lowering (CRUSH-250), and the builtin/method registry this ticket proposed becomes part of that lowering's design. `lower_swc.rs` is frozen for `.js`, so splitting it is wasted work. Original problem, kept for context: Almost every parity ticket edits `crates/crush-lang-js/src/lower_swc.rs` (a single large match). Handed to parallel agents, they will conflict constantly. Builtins and methods (`Math.floor`, `s.toUpperCase()`, `a.indexOf()`) are hand-written match arms, so each new one is a code change in the hottest file.

## Success criteria

- [ ] `lower_swc.rs` split into modules by area (statements, expressions/operators, calls/builtins, objects/arrays, functions), with **no behaviour change**: the full JS test set and the walker set pass unchanged.
- [ ] A table-driven registry for global builtins and receiver methods (name, arity, lowering: a capability name, an op, or a custom lowering fn) used by the call lowering, so tickets 14/15/17 mostly add table rows.
- [ ] Unknown builtins/methods fail with "`X` is not supported by the JS walker yet", never "unknown capability: X" or "uninitialised slot".

## Technical approach

- Mechanical split first, one commit; the registry second. Land quickly: it unblocks parallel work.

## Files to modify

- `crates/crush-lang-js/src/lower_swc.rs` → `crates/crush-lang-js/src/lower/*.rs`

## Non-goals

- Any new feature.

## Dispatch

**The bar (from the spike, `.jagent/planning/research/2026-10-15-JS-TS-parity-spike.md`):** the crush VM prints byte-for-byte what `node` prints; the AOT Rust/C backends are exact **or fail at compile time**; nothing is ever silently wrong. Every case you fix lands as a corpus program under the harness (CRUSH-zorro-4) with a `.out` generated by real `node`.

Do not dispatch. The data-driven builtin/method table requirement moved to CRUSH-250's success criteria.

- Work in a worktree under `crush-ast/.jagent/worktrees/<you>` (a sibling of the `buckets` symlink; deeper paths break the build).
- Reference implementation: `node` on PATH (v26; TypeScript runs with built-in type stripping). Never hand-write a `.out`.
- `crates/crush-lang-js/src/lower_swc.rs` is shared by most tickets. Until CRUSH-zorro-11 lands, keep edits local to the area you own and merge `origin/main` often; after it lands, add entries to the builtin/method table instead of new match arms.
- Gates before the PR: `cargo test -p crush-lang-js -p crush-lang-sdk -p crush-aot`, the walker set, and clippy. A new loud error must say what isn't supported, never "load from uninitialised slot".
