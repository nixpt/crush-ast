## Problem

`console.log([1, 'a', true, null], [1.5*4])` prints `[1, a, true, null] [6.0]`; node prints `[ 1, 'a', true, null ] [ 6 ]`. `console.log({a: 1, b: 'two'})` prints `{a: 1, b: two}`; node prints `{ a: 1, b: 'two' }`. Silently wrong for any program that logs a container.

## Success criteria

- [ ] `console.log` of arrays, nested arrays, objects, nested objects, empty `[]`/`{}`, strings inside containers (quoted, with node's escaping), numbers in JS style, `null`, `undefined` and booleans match node's `util.inspect` defaults.
- [ ] Node's line breaking for long or deeply nested values (over 72 chars, depth > 2 → `[Object]`) is matched, or explicitly out of scope with a corpus program pinning crush's behaviour as a loud mismatch.

## Technical approach

- A `conv.inspect(value, "js")` capability (one implementation in crush-vm, mirrored in the AOT runtimes) used by the `console.log` lowering for non-string arguments.

## Files to modify

- `crates/crush-vm/src/num_text.rs` (or a new `js_inspect.rs`)
- `lower_swc.rs` (console.log lowering)
- AOT runtimes

## Non-goals

- Maps/Sets/class instances (later tickets); colours; `%s`/`%d` format specifiers (separate, loud).

## Dispatch
