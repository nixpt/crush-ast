## Problem

`console.log([1, 'a', true, null], [1.5*4])` prints `[1, a, true, null] [6.0]`; node prints `[ 1, 'a', true, null ] [ 6 ]`. `console.log({a: 1, b: 'two'})` prints `{a: 1, b: two}`; node prints `{ a: 1, b: 'two' }`. Silently wrong for any program that logs a container.

## Success criteria

- [ ] `console.log` of arrays, nested arrays, objects, nested objects, empty `[]`/`{}`, strings inside containers (quoted, with node's escaping), numbers in JS style, `null`, `undefined` and booleans match node's `util.inspect` defaults.
- [ ] Node's line breaking for long or deeply nested values (over 72 chars, depth > 2 → `[Object]`) is matched, or explicitly out of scope with a corpus program pinning crush's behaviour as a loud mismatch.

## Technical approach

- A `conv.inspect(value, "js")` capability (one implementation in crush-vm, mirrored in the AOT runtimes) used by the `console.log` lowering for non-string arguments.

## Files to modify

- `crates/crush-vm/src/num_text.rs` (or a new `js_inspect.rs`)
- `lower_swc.rs` (console.log lowering)
- AOT runtimes

## Non-goals

- Maps/Sets/class instances (later tickets); colours; `%s`/`%d` format specifiers (separate, loud).

## Dispatch

**The bar (from the spike, `.jagent/planning/research/2026-10-15-JS-TS-parity-spike.md`):** the crush VM prints byte-for-byte what `node` prints; the AOT Rust/C backends are exact **or fail at compile time**; nothing is ever silently wrong. Every case you fix lands as a corpus program under the harness (CRUSH-zorro-4) with a `.out` generated by real `node`.

- Work in a worktree under `crush-ast/.jagent/worktrees/<you>` (a sibling of the `buckets` symlink; deeper paths break the build).
- Reference implementation: `node` on PATH (v26; TypeScript runs with built-in type stripping). Never hand-write a `.out`.
- `crates/crush-lang-js/src/lower_swc.rs` is shared by most tickets. Until CRUSH-zorro-11 lands, keep edits local to the area you own and merge `origin/main` often; after it lands, add entries to the builtin/method table instead of new match arms.
- Gates before the PR: `cargo test -p crush-lang-js -p crush-lang-sdk -p crush-aot`, the walker set, and clippy. A new loud error must say what isn't supported, never "load from uninitialised slot".
