## Problem

Also listed (partly stale) in CRUSH-199; this ticket supersedes its block-statement half. A standalone block statement `{ ... }` is dropped entirely by the swc lowering (`Stmt::Block(_) => None`, lower_swc.rs ~692): `{ console.log(5); } console.log(6);` prints only `6`, and `let x = 1; { x = 2; } console.log(x);` prints `1` (node: `2`). Blocks under `if`/loops work.

## Success criteria

- [ ] Both programs above match node on the VM and on AOT Rust and C.
- [ ] Block scoping holds: `let x = 1; { let x = 2; console.log(x); } console.log(x);` prints `2` then `1` (an inner `let` must not clobber the outer binding; see the spike's note on name-keyed slots).
- [ ] No other statement kind falls through to a silent drop: the catch-all arm in statement lowering becomes a loud error.

## Technical approach

- Find the statement match in `lower_swc.rs` that ignores `Stmt::Block`; lower it to its statements in a nested scope.
- Shadowing: rename an inner `let`/`const` that shadows an outer one (alpha-rename), because crush locals are keyed by name per function (`casm_to_vm` `slot_map`).

## Files to modify

## Non-goals

- `var` hoisting semantics beyond what already works.
