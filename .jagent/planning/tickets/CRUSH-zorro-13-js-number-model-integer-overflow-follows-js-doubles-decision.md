## Problem

JS numbers are IEEE doubles. crush has `Int(i64)` and `Float(f64)`, and integer overflow is an error: `2 ** 53 + 1` and `2 ** 64` fail with "arithmetic overflow"; node prints `9007199254740992 18446744073709552000`. Integers above 2^53 also print differently.

## Decision (owner, 2026-10-15): option (a)

JS arithmetic **promotes `Int` to `Float` on overflow**, in `js.add`/`js.sub`/`js.mul`/`js.pow` and the matching
unary/compound forms. Concretely:
- An integer result that fits in `i64` stays `Int`, so indexing, loop counters and `.length` keep integer
  semantics, and nothing changes for programs that never overflow.
- A result that would overflow `i64` is computed in `f64` and becomes `Float` instead of erroring. Output then
  matches node, which prints doubles.
- Safe integers (|n| ≤ 2^53 − 1) print exactly as node does. Beyond that, the `Float` follows node's double
  formatting (`2 ** 64` → `18446744073709552000`).
- Integer literals above `i64` range (e.g. `18446744073709551616`) lower to `Float`.
- Not in scope, stays loud: BigInt (`10n`).
- Engines: the scheduler VM and the portable VM are exact vs node. FastVM/JIT/AOT match or refuse at compile time
  (the spike's bar). The overflow promotion must not silently wrap anywhere.

## Success criteria

- [x] An owner-approved rule, recorded in the spike doc and dejavue: **(a)**, above. Options:
  (a) JS arithmetic promotes Int to Float on overflow (`js.add`/`js.mul`/`js.sub`/`js.pow`);
  (b) the JS walker makes every numeric literal and result a Float;
  (c) leave it loud.
  Recommendation: (a). It keeps ints for indexing and loops and matches node's output for all safe integers.
- [ ] The probe programs `2**53+1`, `9007199254740993`, `2**64`, `Number.MAX_SAFE_INTEGER + 2` match node, or are loud under (c).
