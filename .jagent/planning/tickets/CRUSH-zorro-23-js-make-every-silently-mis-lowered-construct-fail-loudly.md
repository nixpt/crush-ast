## Problem

Interim safety for the swc path while CRUSH-250 is built. Besides bare blocks, labeled break/continue and `finally` (now also covered here; see z-5/6/7), the swc lowering turns several constructs into something that runs and prints wrong output (from a code read of lower_swc.rs; overlaps CRUSH-238, which covers the same pattern across walkers):
- class `constructor`, static blocks, private methods and accessors are dropped (`_ => {}` ~143), and `extends` is ignored;
- `yield x` just evaluates `x` (~1257), and `function*` isn't flagged;
- object spread is dropped (~1049) and `Prop::Assign` too;
- computed object keys all become `"[]"` (~1626);
- setter bodies become empty;
- spread in array literals and call arguments loses its `...` (~970, ~1422);
- `for-in` over an array yields elements;
- TS `enum`/`namespace` are dropped (~434);
- other export forms become a no-op comment block (~229, ~272);
- `console.error`/`console.warn` go to stdout.

## Success criteria

- [ ] Bare block statements, labeled `break`/`continue`, and `try`/`finally` fail loudly on the swc path (their real implementation is z-5/6/7 in the new lowering).
- [ ] Each construct above either works (when its area ticket lands) or fails at walk time with "`<construct>` is not supported by the JS walker yet". None runs silently.
- [ ] Every catch-all arm in `lower_swc.rs` that returns `None`/`Null`/an empty body for an unknown node is replaced with a loud error, so new silent drops can't appear (the statement catch-all is CRUSH-zorro-5).
- [ ] Each case has a corpus program in the harness's known-loud allow-list (so the area ticket that implements it flips it to match).
- [ ] `console.error`/`console.warn` write to stderr, as node does.

## Technical approach

- Mostly replacing `_ => {}` / `None` / `NullLiteral` arms with `bail!`. Keep each message specific.

## Dispatch

**The bar (from the spike, `.jagent/planning/research/2026-10-15-JS-TS-parity-spike.md`):** the crush VM prints byte-for-byte what `node` prints; the AOT Rust/C backends are exact **or fail at compile time**; nothing is ever silently wrong. Every case you fix lands as a corpus program under the harness (CRUSH-zorro-4) with a `.out` generated by real `node`.

**Parser decision (owner, 2026-10-15): option B.** JS gets one frontend in crush-ast, a new `boa_parser` 0.22 lowering with a scope/semantic pass (**CRUSH-250**, widened; it absorbs bozo's BOZO-M7-1 design). swc stays only to strip TypeScript types (CRUSH-zorro-8). `lower_swc.rs` is frozen for `.js` apart from making silent constructs loud (CRUSH-zorro-23).

Highest-leverage P0 after the harness: it turns the remaining *unknown* silent bugs into allow-listed loud ones, which the area tickets then fix.
