## Problem

Besides the P0s with their own tickets, the swc lowering turns several constructs into something that runs and prints wrong output (from a code read of lower_swc.rs; overlaps CRUSH-238, which covers the same pattern across walkers):
- class `constructor`, static blocks, private methods and accessors are dropped (`_ => {}` ~143), and `extends` is ignored;
- `yield x` just evaluates `x` (~1257), and `function*` isn't flagged;
- object spread is dropped (~1049) and `Prop::Assign` too;
- computed object keys all become `"[]"` (~1626);
- setter bodies become empty;
- spread in array literals and call arguments loses its `...` (~970, ~1422);
- `for-in` over an array yields elements;
- TS `enum`/`namespace` are dropped (~434);
- other export forms become a no-op comment block (~229, ~272);
- `console.error`/`console.warn` go to stdout.

## Success criteria

- [ ] Each construct above either works (when its area ticket lands) or fails at walk time with "`<construct>` is not supported by the JS walker yet". None runs silently.
- [ ] Every catch-all arm in `lower_swc.rs` that returns `None`/`Null`/an empty body for an unknown node is replaced with a loud error, so new silent drops can't appear (the statement catch-all is CRUSH-zorro-5).
- [ ] Each case has a corpus program in the harness's known-loud allow-list (so the area ticket that implements it flips it to match).
- [ ] `console.error`/`console.warn` write to stderr, as node does.

## Technical approach

- Mostly replacing `_ => {}` / `None` / `NullLiteral` arms with `bail!`. Keep each message specific.
