## Problem

Baseline, all loud: `undefined` as a value and as a missing property or index (`[1][5]` → crush "index out of range", node `undefined`); `typeof` (Unsupported op); `??` (Unsupported op); `?.` ("expected map, got null"); `NaN`/`null == undefined` comparisons ("uninitialised slot"); bitwise `& | ^ ~ << >> >>>` (Unsupported op); `1/0`, `-1/0`, `0/0` ("division by zero"; node: `Infinity -Infinity NaN`).

## Success criteria

- [ ] Every probe in the spike's *values & operators* group matches node on the VM; AOT exact-or-loud.
- [ ] `undefined` is distinct from `null` where node distinguishes them (printing, `==` vs `===`, `typeof`), using a dedicated value or a documented encoding.
- [ ] Bitwise ops use ToInt32/ToUint32 semantics (`-16 >>> 28` = `15`).
- [ ] Division by zero: #189 deliberately made JS `÷0` a loud error rather than `Infinity`, which is allowed under the bar. Changing it to IEEE results is a choice for this ticket's PR to raise, not a requirement.
- [ ] `Infinity`, `NaN` and `undefined` work as identifiers (today they are undefined variables).
- [ ] `&&`/`||` value semantics and `==` coercion are CRUSH-zorro-22, not this ticket.

## Technical approach

- `js.*` capabilities where crush semantics differ (as with `js.div` in #189); `typeof` from the runtime type; `?.` as a null/undefined check plus short-circuit.

## Files to modify

- `lower` (after the split)
- `crates/crush-vm/src/arithmetic.rs`
- AOT runtimes

## Non-goals

- `instanceof` (needs the object model).

## Dispatch

**The bar (from the spike, `.jagent/planning/research/2026-10-15-JS-TS-parity-spike.md`):** the crush VM prints byte-for-byte what `node` prints; the AOT Rust/C backends are exact **or fail at compile time**; nothing is ever silently wrong. Every case you fix lands as a corpus program under the harness (CRUSH-zorro-4) with a `.out` generated by real `node`.

**Parser decision (owner, 2026-10-15): option B.** JS gets one frontend in crush-ast, a new `boa_parser` 0.22 lowering with a scope/semantic pass (**CRUSH-250**, widened; it absorbs bozo's BOZO-M7-1 design). swc stays only to strip TypeScript types (CRUSH-zorro-8). `lower_swc.rs` is frozen for `.js` apart from making silent constructs loud (CRUSH-zorro-23).

**Split of work:** the values & operators semantics are **runtime-library** capabilities in crush-vm (`js.*`, mirrored in AOT). That's the shared JS runtime bozo's BOZO-M7-2 planned, now in crush-ast, and it can be built and unit-tested before CRUSH-250. Wiring them into the lowering uses CRUSH-250's builtin/method table. Read 'registry (after CRUSH-zorro-11)' above as 'CRUSH-250's table'.
